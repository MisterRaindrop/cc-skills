# Knowledge Management Plugin

Obsidian-powered knowledge management for Claude Code. Archive dev experiences with `/knowledge:save`, maintain knowledge freshness with `/knowledge:maintain`.

## What It Does

This plugin turns Obsidian into Claude Code's external memory:

- **`/knowledge:save`** — Archive the current session's experiences (bug fixes, architecture decisions, implementation insights) to your Obsidian vault with structured frontmatter, auto-classification, and index updates
- **`/knowledge:maintain`** — Scan the vault for expired notes, inbox backlog, missing metadata, and orphaned plans. Interactively archive, extend, or clean up

## Architecture

```
Claude Code Session
        |
        v
  /knowledge:save
  Archive to Obsidian vault
        |
        v
  Knowledge/Projects/{project}/
  - development/    (dev experience)
  - troubleshooting/ (pitfall records)
        |
        +-> Patterns/_index.md (cross-project patterns)
        +-> _inbox/ (Wiki drafts)
        |
        v
  Next Session
  - MEMORY.md auto-loads key summaries
  - search_vault_smart retrieves details on demand
        |
        v (periodically)
  /knowledge:maintain
  - Clean expired notes (review_after driven)
  - Process inbox backlog
  - Archive orphaned plans
```

## Prerequisites

### 1. Install Obsidian Plugins

**Order matters: Install Local REST API FIRST, then MCP Tools.**

#### Local REST API

1. Obsidian -> Settings -> Community Plugins -> Browse
2. Search **Local REST API** -> Install -> Enable
3. Plugin settings:
   - Enable **Non-encrypted (HTTP) Server**
   - Default port: `27123`
   - Note the generated **API Key**
4. Verify: visit `http://localhost:27123` in browser

#### MCP Tools

1. Community Plugins -> Search **MCP Tools** -> Install -> Enable
2. Plugin settings: enter the API Key from Local REST API
3. The plugin generates an executable at:
   ```
   <vault-path>/.obsidian/plugins/mcp-tools/bin/mcp-server
   ```
4. Ensure it's executable:
   ```bash
   chmod +x <vault-path>/.obsidian/plugins/mcp-tools/bin/mcp-server
   ```

### 2. Configure MCP Connection in Claude Code

Edit `~/.claude.json` to add the Obsidian MCP server:

```json
{
  "mcpServers": {
    "obsidian": {
      "type": "stdio",
      "command": "<vault-path>/.obsidian/plugins/mcp-tools/bin/mcp-server",
      "args": [],
      "env": {
        "OBSIDIAN_API_KEY": "<your-api-key>",
        "NO_PROXY": "localhost,127.0.0.1",
        "no_proxy": "localhost,127.0.0.1"
      }
    }
  }
}
```

| Field | Value | Notes |
|-------|-------|-------|
| `type` | `"stdio"` | Communicates via stdin/stdout |
| `command` | Absolute path to mcp-server | Auto-generated by MCP Tools plugin |
| `OBSIDIAN_API_KEY` | API Key string | From MCP Tools plugin settings |
| `NO_PROXY` | `localhost,127.0.0.1` | **Required** — prevents proxy from intercepting local traffic |

Verify:
```bash
claude mcp list
# obsidian should show: Connected
```

### 3. Set Up Vault Directory Structure

Create the following structure in your Obsidian vault:

```
vault/
├── Knowledge/
│   ├── _taxonomy.md            # Classification rules (Claude reads before archiving)
│   ├── _inbox/                 # Unsorted staging area + Wiki drafts
│   │   └── README.md
│   ├── Projects/               # Experiences organized by project
│   │   └── {project-name}/
│   │       ├── _index.md       # Project index (wikilink list)
│   │       ├── development/    # Dev experiences, architecture decisions
│   │       └── troubleshooting/# Pitfall records, bug analysis
│   └── Patterns/               # Cross-project patterns (reference layer)
│       └── _index.md           # Wikilinks only, no original content
└── Wiki/                       # Personal tech encyclopedia (optional)
    └── {domain}/{tech-stack}/
```

### 4. Create the Classification Rules File

`Knowledge/_taxonomy.md` is the core rules file. Claude reads it before every `/knowledge:save` execution.

Create it with at minimum:

```markdown
# Knowledge Classification Rules

> Decision reference for Claude Code when archiving.
> Must be read before every /knowledge:save execution.

## Classification Principles

| Content Type | Archive Location |
|-------------|-----------------|
| Dev experience, implementation, architecture decisions | `Projects/{project}/development/` |
| Pitfall records, bug analysis, troubleshooting | `Projects/{project}/troubleshooting/` |
| Unknown project | `_inbox/` |

## Frontmatter Specification

Every note must include:

    ---
    title: Concise title
    date: YYYY-MM-DD
    project: project-name
    tags: [tag1, tag2]
    source: claude-code-session
    status: active
    confidence: high
    content_type: session
    review_after: YYYY-MM-DD
    ---

### content_type values

| Value | Meaning | review_after |
|-------|---------|-------------|
| `permanent` | Long-term (architecture, debug insights) | date + 180 days |
| `session` | Session record | date + 30 days |
| `plan` | Planning document | date + 7 days |
| `todo` | Task list | date + 14 days |
| `snapshot` | Config/doc snapshot | date + 30 days |

## Naming Convention

Format: `YYYY-MM-DD-short-description.md`

## Update Rules

1. Before archiving, search for similar content with `search_vault_smart`
2. High similarity -> append to existing file, update `date`
3. No match -> create new file
4. After create/update, sync project `_index.md`
5. Cross-project value -> add wikilink in `Patterns/_index.md`

## Known Projects

| Folder Name | Description |
|------------|-------------|
| (add your projects here) | |
```

Customize this file for your projects and preferences.

### 5. Create Project Index Files

For each project, create `Knowledge/Projects/{project}/_index.md`:

```markdown
---
project: my-project
---

# my-project Knowledge Index

One-line project description.

## Development

_(No notes yet)_

## Troubleshooting

_(No notes yet)_
```

## Troubleshooting

### `claude mcp list` shows obsidian as Failed

1. Is Obsidian running? (must stay open)
2. Is Local REST API plugin enabled?
3. Is the `mcp-server` path correct?
4. Does the API Key match?
5. Is `NO_PROXY` set? (proxy can intercept localhost traffic)

### Some project directories can't connect, others work

Global vs project-level MCP config conflict in `~/.claude.json`. Standardize to a single global config using the local binary approach.

### MCP Tools keeps asking for API Key

Install order bug. Uninstall MCP Tools -> Confirm Local REST API works -> Reinstall MCP Tools.

### Notes not found after /knowledge:save

- Check vault path permissions
- Press Ctrl+R in Obsidian to refresh the vault
